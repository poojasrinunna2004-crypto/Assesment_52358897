# Reflection

The clearest success was making the information flow visible instead of treating the four agents as unrelated character descriptions. The Topic Researcher produces a brief with source IDs, the Quiz Maker builds questions from those records, the Explainer receives the same brief, and the Fact-Checker receives all three outputs. The saved session includes those task links, source URLs, questions, answers, and check results. Using LangChain's `@tool` interface for retrieval, quiz construction, and claim checking kept tool inputs explicit and made the offline workflow straightforward to test.

One limitation is that the bundled photosynthesis pack makes the demonstration reliable without credentials or a network, but it is intentionally narrow. Other topics use Wikipedia extracts; those extracts may be incomplete, and the simple quiz fallback is less pedagogically strong than a human-written question. The Fact-Checker also performs wording alignment against the supplied notes, not independent verification. It can miss a correct paraphrase or accept a claim whose terms happen to appear together without proving the relationship. The Explainer uses a prepared explanation for the sample topic rather than generating a novel lesson.

If I extended this project, I would add a configurable language model to help draft explanations and distractors while retaining citations and requiring the Fact-Checker to review every generated statement. I would improve evidence matching with claim-to-source links and a human review step, add source-quality and freshness metadata, and expand the tested reference pack. I would also test API timeouts, malformed responses, empty searches, and source disagreements more extensively. The current design favors a transparent, repeatable assessment demo over pretending that a small keyword checker is a complete fact-checking system.
